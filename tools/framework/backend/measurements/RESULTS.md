### Findings

- **The Aspire dashboard is the biggest single item after weeks of uptime**: 0.9-1.7 GiB per project on firstvds
  (in-memory telemetry without limits), 75-84 MiB on the fresh deploys of ovh. Removing it frees ~3.8 GiB on firstvds
  (storytale included, but storytale is not redeployed).
- **A .NET role costs 100-130 MiB fresh** (ovh: silo 106-108, coordinator 105-125, meta 110-127, game 94-121, console
  124-144 anon), five roles 540-630 MiB per project; on firstvds the same roles are 35-60 MiB in RAM and the rest in swap.
- **firstvds swaps**: 5.4 GiB of private memory is in swap with 2.9 GiB available. Coolify itself costs ~400 MiB per host.

## 2026-11-25, pixel-swarm as a monolith (ovh)

Snapshot `results/2026-11-25-monolith`, 07:11 UTC, no load. pixel-swarm runs the monolith (one container `backend`,
every role, `DOTNET_gcServer=0`, branch `deploy-monolith`), 10 minutes after its deploy; the "before" containers had run
2-3 hours, so the monolith has had less time to grow. A cross-check at the same uptime: `docker stats` of the five
services at 06:35 UTC (2 h), right before the switch, was 795 MiB (silo 195, console 175, meta 158, coordinator 139,
game 128).

| pixel-swarm, MiB | Before: 5 services, server GC | After: monolith, workstation GC |
|---|---|---|
| .NET, stats | 816 | 172 |
| .NET, cost (anon + swap) | 542 | 99 |
| aspire-dashboard, cost | 75 | 95 |
| Postgres + pgbouncer + web, cost | 48 | 58 |
| Total, cost | 666 | 252 |

The roles themselves cost ~4-5 times less in one process: one runtime, one JIT and GC heap instead of five, and the
workstation GC. The local measurement (fresh Postgres, 90 s settle): server GC 159 MiB, workstation 136 MiB, workstation +
`DOTNET_GCConserveMemory=5` 137 MiB (stats).

### Findings

- **The monolith costs a third of the five services**: .NET 84 against 252-276 MiB at the same idle age, the project
  141-142 against 315-342. Prod at a similar age agrees (99 against 542 after 2-3 h, the section above: the services
  grow more with time).
- **GC**: in the monolith the workstation GC saves a quarter of the .NET cost (110 -> 84); `DOTNET_GCConserveMemory=5`
  adds nothing at idle (84). In the five services the GC makes no difference in cost at 5 minutes (251-260, within the
  spread of the repeat), only in stats (server GC keeps more of its reserved pages resident: 713 against 614-622).
- **Telemetry**: the stack costs 26-38 MiB for three containers against 84-92 for `aspire-dashboard` fresh (and 0.9-1.7
  GiB after weeks on firstvds, the first section); the .NET side also costs 10-40 MiB less without the gRPC exporter and the
  metrics. On a host the stack is shared by all its games, the dashboard runs once per game.
- **Repeat**: the monolith gives the same numbers (142 / 141), the services differ by 9% (315 / 342, the .NET part 252 /
  276): compare local variants of the five services with that margin in mind.
- **PSS** of the .NET processes is 2-3 times their cost: it counts the mapped runtime, framework and application
  assemblies (file pages, shared and reclaimable), which cost the host page cache, not private memory.
- Once a start of the monolith failed on the loaded machine (load average 50; `host Silo stopped by itself`), the rerun
  passed; no load scenario was run (README.md § Repeat: no headless bots, console benchmarks only in Development).
