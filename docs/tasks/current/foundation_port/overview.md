# Foundation port: перенос фиксов из peace-data-reborn

`/projects/peace-data-reborn` (дальше A) — форк этого проекта (B), сделанный около 2026-09-23. На этапе 123 "Foundation" в A исправили много проблем общего стека:
- безопасность: тикеты сессий, гостевой секрет, консоль, внутренние эндпоинты, CORS;
- сеть: websocket reader/writer, ErrorResponse, union-теги, хэш протокола, keep-alive;
- Orleans-инфраструктура: транзакции, StateCollection, messaging, эпохи, мигратор;
- Lifetime/Reactive;
- ядро клиента и кодоген.

Сверка 2026-10-20 показала, что инфраструктурные, reactive- и core-файлы B **побайтно совпадают** с A на старте этапа (`0a67a0b08^`). Сетевые и сессионные файлы совпадают или проще. Значит, в B есть почти все найденные в A баги, а большинство фиксов переносится патчем коммита. Не переносятся только игровые фиксы A (оружие, боссы, этажи, комнаты).

## Источник: как брать фиксы из A

- Коммит A указан у каждой задачи: `git -C /projects/peace-data-reborn show <hash>`.
- Описания багов A лежат в `/projects/peace-data-reborn/docs/roadmap/foundation/`: `01_security.md` (F1), `02_bugs.md` (F2), `03_protocol.md` (F3), `00_hygiene.md` (F0), `04_core_extraction.md` (F4), `06_backend_modules.md` (F6), `07_gameplay.md` (F7).
- Если файл B совпадает с A на старте этапа (`diff <(git -C /projects/peace-data-reborn show 0a67a0b08^:<path>) <path>` пустой), накладывать патч:
  `git -C /projects/peace-data-reborn diff <hash>^ <hash> -- <paths> | git apply --3way`.
  Патчи идут в порядке коммитов A, игровые хунки выбрасываются.
- Если файл отличается, переносить вручную только хунки фикса.
- Тесты A переносить вместе с фиксом (пути указаны в задачах).
- Правила кода B: `CLAUDE.md` и `.claude/docs/*`. Комментарии в коде на английском.
- Различия окружения:
  - B на Unity `6000.7.0b1` (Mono), A на CoreCLR-альфе `7000`. Фиксы A под особенности CoreCLR (формат float, `string.GetHashCode` на каждый процесс) проверять на применимость.
  - Документация агентов B лежит в `.claude/docs`, правила — в `CLAUDE.md`.

- Сам задачи не делает. Запускает исполнителей: фоновые `Agent`, одна задача или связка мелких задач одного файла. Промпт короткий: ID, путь к файлу задачи, этот overview, `executor_brief.md`.

- Собирает вопросы пачками (`AskUserQuestion`).
- Принимает работу по критериям задачи, ведёт статусы и журнал.
- Коммитит готовые задачи: одна задача (или связка) — один коммит, path-scoped `git commit -- <paths>`. В теле коммита пишет `(port of peace-data-reborn <hash>)`.
- Код не правит, кроме документов этой папки.
- Деплой (Coolify, WebGL) только по просьбе пользователя.

### Протокольный релиз

N4, N6, N7, S3, S4, N10 меняют протокол или handshake. Они коммитятся по отдельности, но выкатываются **одним** деплоем: сначала бэкенд, сразу за ним клиент. Без хэша протокола (N7) закешированные WebGL-клиенты ломаются молча. В `orchestrator_handoff.md` собрать чек-лист деплоя по образцу A (`/projects/peace-data-reborn/docs/tasks/current/123_foundation/orchestrator_handoff.md`, раздел "Чек-лист деплоя"):
- новые секреты: `SESSION_TICKET_SECRET`, `GUEST_LEGACY_LOGIN_UNTIL`, `CONSOLE_TOKEN`, `ASPIRE_TOKEN`, `OTEL_API_KEY`;
- бэкап БД и миграция гостей;
- смена ClusterId;
- версия pgbouncer.

## Правила для исполнителей (скопировать в executor_brief.md)

1. Шаг 0: подтвердить баг в B чтением кода или падающим тестом и записать в `<ID>/handoff.md`. Если баг не подтвердился — стоп, отчёт.
2. Переносить минимально: фикс и его тесты. Не тянуть игровой код A и не рефакторить окружение.
3. Fail-fast (`CLAUDE.md`): никаких новых `if (x == null) return;` и пустых `catch`.
4. Проверка бэкенда: `dotnet build backend/backend.slnx`, затем `dotnet test backend/Tools/Tests/Tests.csproj` (сначала новые тесты с фильтром, потом полный прогон; логи — `.claude/docs/TESTING.md`). Тесты, которые без Docker пропускаются, указать в отчёте.
5. Проверка клиента: компиляция в редакторе B без ошибок, EditMode-тесты через MCP. Только когда оркестратор выдал редактор.
6. Не коммитить, коммитит оркестратор. В отчёте: изменённые файлы, результат сборки и тестов, отличия от A.
7. Отчёт по-русски, коротко.
