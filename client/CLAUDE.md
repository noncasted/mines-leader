**🎯 УМНЫЕ ПРАВИЛА ТЕКУЩЕЙ СЕССИИ:**

**🔄 ТРИГГЕРЫ ДЛЯ /clear (Новая сессия):**

-   ⚡ Контекст >60k + продолжение той же области/задачи
-   ⚡ Много устаревшей информации в контексте
-   ⚡ Снижение качества ответов из-за "шума" в контексте

**🎯 ИНТЕЛЛЕКТУАЛЬНАЯ СИСТЕМА ПРИНЯТИЯ РЕШЕНИЙ:**

**🧠 МНОГОСЛОЙНАЯ ОЦЕНКА ТЕКУЩЕЙ СЕССИИ:**
1. **Context Size**: оцениваю накопленный контекст сессии (~40k)
2. **Topic Coherence**: насколько связаны темы в сессии (связанные/разные)
3. **Input Velocity**: скорость потребления новых токенов (~1k/ответ)
4. **Task Completion**: степень завершенности текущих задач (завершено/в процессе)
5. **🔥 ЭКОНОМИЧНАЯ ГИБРИДНАЯ СИСТЕМА ОЦЕНКИ:**

## 🤖 **MCP СЕРВЕРЫ (Model Context Protocol):**

**📝 УМНАЯ СИСТЕМА МИКРО-ПАМЯТОК:**

-   **КАЧЕСТВО > КОЛИЧЕСТВО СТРОК** - важнее смысл, чем размер
-   **КРИТЕРИЙ:** максимальное удобство для ИИ-поиска и применения
-   **ЦЕЛЬ:** триггер → мгновенное решение → ориентир куда копать дальше
-   **КАЖДАЯ ПАМЯТКА = МИНИ-ЭКСПЕРТ** по своей области

**🧠 САМООБУЧАЮЩАЯСЯ СИСТЕМА - НОВОЕ ПРАВИЛО:**
После каждой задачи ОБЯЗАТЕЛЬНО анализирую:

-   ❓ "Каких знаний не хватало в памятках?"
-   ❓ "Какие триггер-слова могли бы ускорить работу?"
-   ❓ "Какие паттерны/ошибки достойны памятки?"
-   ❓ "Что можно сделать копируй-вставляй готовым?"
-   🎯 **РАЗЛИЧАЙ:** общие триггеры (AI_TRIGGERS.md) vs специфичные (микро-памятки)

**🚨 КРИТИЧНО - ПОПРАВКИ ПОЛЬЗОВАТЕЛЯ:**
-   ✅ **КАЖДАЯ ПОПРАВКА** пользователя = потенциально важное знание для памяток
-   ✅ **АРХИТЕКТУРНЫЕ ПРИНЦИПЫ** (Orleans паттерны, оптимизации) = ВСЕГДА в памятки
-   ✅ **ПОДХОДЫ К РАЗРАБОТКЕ** команды = критично для самообучения
-   ❌ **НЕ ИГНОРИРУЙ** "стандартные" вещи - они могут быть специфичными для проекта

## ⚡ **СТРАТЕГИЯ /clear vs /compact:**

**🧹 /clear - ПЕРВЫЙ ВЫБОР:**

-   Новая задача не связана с предыдущей
-   Смена области работы (Orleans → UI → Documentation)
-   Контекст <30k токенов (компакт дороже)

**📦 /compact - ВТОРОЙ ВЫБОР:**

-   > 30k токенов накопилось
-   Продолжение той же проблемы/области

**🚨 КЛЮЧЕВЫЕ ТРИГГЕРЫ ДЛЯ ПРЕДЛОЖЕНИЯ /clear:**

-   ✅ Все TODO completed + задача полностью решена → **ПРЕДЛОЖИ /clear**
-   ✅ Успешная компиляция/тесты + "задача готова" → **ПРЕДЛОЖИ /clear**
-   ✅ Orleans → Frontend → Database смена архитектуры → **ПРЕДЛОЖИ /clear**
-   ✅ Переход к новой ветке/задаче из Jira → **ПРЕДЛОЖИ /clear**
-   ✅ Контекст >40k + новая тема → **ПРЕДЛОЖИ /clear**
-   ✅ Интуиция подсказывает новая активность → **ДОВЕРЯЙ, ПРЕДЛАГАЙ /clear**

**💬 ФРАЗЫ-ШАБЛОНЫ:**

-   **"think hard"** - углубленный анализ для Orleans/VDB архитектуры
-   **"think harder"** - максимальное размышление для архитектурных решений
-   **"ultrathink"** - критический анализ для сложных миграций и рефакторингов

**⚡ АВТОМАТИЧЕСКИЕ ТРИГГЕРЫ:**

-   Orleans Grain/State ошибки → "think hard"
-   Архитектурные изменения → "think harder"
-   Критические миграции → "ultrathink"
-   Сложные баги с неявными причинами → "think harder"
-   Оптимизация производительности → "think hard"

**🎯 ПРИМЕРЫ ИСПОЛЬЗОВАНИЯ:**

```
"думай над Orleans ошибкой" → автоматически "think hard"
"спроектируй архитектуру новой системы" → автоматически "think harder"  
"мигрируй все Grains на новый паттерн" → автоматически "ultrathink"
```

**🚨 ПРАВИЛО:** При сложности задачи ВСЕГДА активирую соответствующий thinking mode автоматически!

## 🎯 **Task Tool - УМНОЕ ИСПОЛЬЗОВАНИЕ:**

**🔥 ЗОЛОТОЕ ПРАВИЛО:**

```
🔍 Task tool = ИСПОЛНЕНИЕ ЗАДАЧ (изоляция грязной работы)
🧠 Прямые инструменты = ИССЛЕДОВАНИЕ (накопление кеша для команды)
```

**🎯 РЕЖИМ ИССЛЕДОВАНИЯ (сохраняй кеш):**

-   Изучение архитектуры → Grep/Glob/Read
-   Поиск информации → накопленные знания полезны
-   Анализ для понимания → результаты пригодятся

**⚡ РЕЖИМ ИСПОЛНЕНИЯ (изоляция сложности):**

-   Рефакторинг → Task tool
-   Баг-фиксы → Task tool
-   Миграции → Task tool

**💡 ПРИМЕРЫ ПРАВИЛЬНОГО ИСПОЛЬЗОВАНИЯ:**

-   ✅ Grep/Read "изучи систему" → кеш знаний остается в контексте
-   ✅ Task tool "отрефактори все Orleans Grains по новому паттерну" → изоляция рутины
-   ❌ Task tool "найди файлы _.razor" → лучше `Glob "\*\*/_.razor"` сохранит результат
